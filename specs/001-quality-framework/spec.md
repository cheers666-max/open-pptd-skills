# Feature Specification: 面向 pi 使用的 open-pptd 轻量优化

**Branch**: 001-quality-framework | **Updated**: 2026-09-05
**Status**: 已实施；工具回归通过，首轮20题及两题复测完成；真实生成完成率与内容质量尚未达标。
**用户约束**: 用 pi 调度，主要优化 skills 本身，方案保持简单；既有案例只作回归参考。

## User Scenarios & Testing

### US1 — pi 能按同一套清晰约束完成制作 (P1)

用户希望 skill 提供可直接执行的制作步骤，不依赖固定名称的代理工具，也不要求为每份 PPT 维护复杂元数据。

独立验收：通过同一份作者说明分别走顺序写作和可用时的并行写作；核对共享数字/单位/年份、相邻页职责及最终来源，不增加额外运行平台。

- 宿主没有子代理工具时正常顺序执行，不调用不存在的 task 工具。
- 多页制作共用一份简短 DESIGN_CONTEXT.md；单页可以直接在当前上下文列明约束。
- 同口径异值、理论/实测混淆和重复论点由主写手结合实际页面复核。教学示例和用户私有资料不强制公网链接。
- YAML 富文本、字号/行高估算、图标选择及所选设计风格有明确指引；修改任务只改授权范围。

### US2 — 现有工具的失败及时可见 (P1)

用户希望搜图有进度和截止，渲染与导出出现内容丢失时能定位问题。

独立验收：通用小型样本覆盖后端超时/下载失败、离线、饼图异常、局部页导出、图标丢失和异常 JSON；依赖现有命令即可判断。

- 图片搜索在设定预算内结束；后端候选全部下载/筛选失败时继续下一后端。
- 图片离线模式不访问图片后端或 VLM；仅许可的装饰图可用本地替代，特定产品/人物/证据图缺失保留失败。
- 图表渲染异常、HTML 导出失败、PPTX 图标替换不能伪装成功；报告保留对应页面/元素及原因。
- 机器输出保持可解析，进度写 stderr，失败退出非零；现有有效调用和摘要字段尽量保持兼容。

### US3 — 检查帮助修正文稿，不机械改坏设计 (P2)

用户希望检查能发现已知排版问题，并保留固定页数、页型、教学顺序与模板要求。

独立验收：用富文本/CJK/固定行高、黑字白底、复杂背景及固定页数样本验证；人工看图补充工具未能可靠判断的范围。

- 文本容量标明是估算，不把它当真实排版尺寸或默认自动扩高。
- 正确黑白对比不误报；复杂背景/透明遮挡不确定时只提示复核。
- 节奏检查只提建议，保留页数、页序、页型和额外字段；不规定所有内容页必须有 25–40 个元素。
- 卡片规则先保留并说明几何启发式边界，不因单个案例提阈值或豁免全部封面。

## Functional Requirements

- **FR-001**: 写作步骤适配宿主实际工具，允许顺序或并行执行，不强制额外 pi 扩展。
- **FR-002**: 提供简短共享作者说明：任务边界、设计规则、逐页职责、数字口径与来源、YAML/容量/图标约束。
- **FR-003**: 素材改写完成后，主写手复核全稿或修改范围的事实、来源和叙事；引用齐全不等于事实已核实。
- **FR-004**: 搜图具备单后端和整体预算、流式进度、完整回退、离线图片处理及真实失败诊断。
- **FR-005**: 修复已复现的图表/图标/异常退出和局部页身份问题；现有导出入口提供可读取的完整 warnings。
- **FR-006**: 修复已复现的容量估算与纯色对比误判；无法可靠测量的范围明确说明，不默认自动修布局。
- **FR-007**: 节奏建议保留用户页数及内容语义，设计提示不变成统一数量阈值。
- **FR-008**: 为上述行为补小型正负回归，测试准备失败不能显示通过；最终使用现有命令和 pi 会话 smoke 验证。

## Success Criteria

- **SC-001**: 无子代理工具仍能按 skill 完成制作；共享说明与终审步骤覆盖研究数据、教学示例和指定页编辑。
- **SC-002**: 受控搜图挂起在整体预算 + 最多 2 秒清理内结束；首次进度及时输出，长阶段心跳间隔不超过 5 秒；offline 图片测试无网络/VLM 调用。
- **SC-003**: 已知饼图/图标/导出失败样本不静默成功；局部导出 3、5 页保持原页身份，JSON 可解析且失败非零。
- **SC-004**: 已知正确黑白对比不误报，固定页数/页型不变；复杂视觉结果不冒充确定结论。
- **SC-005**: 现有回归真实执行，新增测试只覆盖此次修复；通用样本可复验，无案例专用规则。

## Scope and Assumptions

保留现有 PPTD、Python/Node 脚本、viewer 和默认 PPTD/PPTX/HTML 交付。按任务授权使用联网能力，凭据存在不等于授权。

日常 skill 无需新质量 gate、全局 JSON Schema、哈希/审阅状态系统、事实数据库、格式能力注册表或 pi 插件。用户追加的开发评测仅在 eval/ 记录独立快照和评阅证据，不进入每次制作流程。数字与叙事先通过共享说明和主写手复核解决；不承诺自动事实验证。CLI 大整理、多平台工程和任意 PPTX 无损往返均不纳入本次。

图片 --offline 的验收范围是图片脚本；不据此宣称现有所有导出依赖安装和字体路径已可零网络运行。完整离线导出仍须先备齐本地依赖与字体。
