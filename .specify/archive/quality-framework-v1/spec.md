# Feature Specification: 通用 Skill 质量框架

**Feature Branch**: 001-quality-framework
**Created**: 2026-09-05
**Status**: Planned — implementation not started
**Input**: 优化 open-pptd skills 项目及框架体系，先使用 SpecKit 规划任务；既有行业分析只作为验证样本。

## User Scenarios & Testing

### User Story 1 - 交付结论有可核验依据 (Priority: P1)

作为制作或编辑演示文稿的用户，我需要知道整套交付检查了什么、哪里有错误、哪里未检查，以及三种交付格式是否保留了内容，避免拿到“导出成功但内容丢失”的文件。

**Why this priority**: 静默丢失图表、图标或页面，以及错误通过的验收，会直接破坏交付。
**Independent Test**: 使用不依赖联网的通用小型文稿，分别注入图表异常、图标替代、缺少格式、过期结果和局部检查，确认每个结果被准确区分。该故事可独立提供结构/导出范围的可靠检查；尚未实现的内容或视觉检查必须显示未检查。

**Acceptance Scenarios**:

1. **Given** 生成了文件但一个图表渲染失败，**When** 进行交付检查，**Then** 指出页面与元素并阻止该交付通过。
2. **Given** 图标被替换为无关字符，**When** 检查导出内容，**Then** 识别信息损失，不能因文件有效而通过。
3. **Given** 仅检查部分页面或结果对应旧版本，**When** 请求整套交付验收，**Then** 指出覆盖不完整或结果过期。
4. **Given** 工具不支持某检查、缺依赖或执行失败，**When** 汇总结果，**Then** 显示未检查及原因，不能等价于零问题。
5. **Given** 用户明确只需要部分输出格式，**When** 进行验收，**Then** 按该任务要求检查，并公开实际覆盖范围。

### User Story 2 - 全稿共享事实、约束和叙事 (Priority: P1)

作为研究、教育、内部汇报或模板编辑用户，我需要各页使用同一份已界定的内容与设计约束，来源可定位，主张与口径不漂移，同时不要求私人数据或教学示例必须有公网引用。

**Why this priority**: 内容一致与准确表达属于框架职责；新增禁令不能代替可执行的协作约束。
**Independent Test**: 分别用外部研究、用户提供数据、教学示例和限定页编辑四类场景，验证来源要求、推导关系、任务范围和共用上下文；无需依赖特定模型或真实联网搜索。

**Acceptance Scenarios**:

1. **Given** 相同指标、时期与统计范围出现不同数值，**When** 内容检查，**Then** 定位冲突；不同年份或分母的数值不被错误合并。
2. **Given** 数字相同但被分别写成理论上限、实测或预测，**When** 跨页审阅，**Then** 提示含义需要核对。
3. **Given** 内部业务数据来自用户文件，或数字被声明为教学示例，**When** 核查来源，**Then** 接受其合法依据类型，不强迫添加公网 URL。
4. **Given** 来源存在但没有证据说明其支持该主张，**When** 汇总结果，**Then** 区分“引用完整”和“依据已核对”。
5. **Given** 多个写作任务读取不同版本约束，**When** 合并全稿，**Then** 识别版本漂移并要求重核受影响内容。
6. **Given** 编辑范围仅包含指定页面，**When** 内容和叙事终审，**Then** 检查修改页及其关联引用，不擅自重写其他页面。
7. **Given** 正文、表格或图表使用了主张，**When** 核查绑定，**Then** 三类内容均可追溯到相应指标或数据。

### User Story 3 - 素材获取有边界且降级可见 (Priority: P2)

作为离线或网络不稳定环境中的用户，我需要素材处理在预算内结束、持续显示进度，并明确哪些素材来自本地、哪些经过替代、哪些仍未解决。

**Why this priority**: 等待无上限和隐式联网会破坏本地工作流；错误替代会改变内容语义。
**Independent Test**: 用可控的成功、超时、下载失败、筛选失败和离线场景，确认回退顺序、截止、报告完整性与零隐式联网。

**Acceptance Scenarios**:

1. **Given** 第一个来源给出候选但全部无法下载或不合格，**When** 尝试下一来源，**Then** 能在剩余预算内继续并记录各次失败原因。
2. **Given** 某任务长期无响应，**When** 到达预算，**Then** 终止相关工作并报告剩余未解决项。
3. **Given** 任务要求离线，**When** 缺少图片、字体或依赖，**Then** 不隐式访问远端；可用本地内容继续，缺项明确报告。
4. **Given** 背景被明确声明为可替代装饰，**When** 无真实素材且允许降级，**Then** 可生成本地装饰，并保留替代记录。
5. **Given** 图片必须体现特定人物、产品或模板内容，**When** 素材不可得，**Then** 保留未解决状态，不能用渐变冒充。
6. **Given** 没有获得联网授权但存在 API 凭据，**When** 运行本地任务，**Then** 凭据存在不会改变联网策略。

### User Story 4 - 排版与设计检查尊重真实能力 (Priority: P2)

作为使用不同设计系统的用户，我需要真实溢出被发现、正确排版不被误改，固定页数和有意连续讲解得到保留。

**Why this priority**: 不可靠的检测和机械设计阈值会反过来降低质量。
**Independent Test**: 使用已知真值的富文本、固定行高、黑白对比、复杂背景、透明覆盖和教学连续页验证；无需修改真实文稿。

**Acceptance Scenarios**:

1. **Given** 内联字号、段落间距或固定行高造成实际溢出，**When** 测量排版，**Then** 报告对应元素与测量依据。
2. **Given** 标准黑字白底，**When** 对比度检查，**Then** 不产生错误的阻断；复杂背景无法可靠判断时说明检查边界。
3. **Given** 指定固定页数或连续教学推导，**When** 规划节奏，**Then** 页数、内容顺序、显式页型和用户字段保持不变，仅提供适用建议。
4. **Given** 表格承载高密度信息或极简设计采用少量元素，**When** 检查设计，**Then** 不以统一元素数量下限判失败。
5. **Given** 某几何模式疑似卡片堆砌，**When** 检查，**Then** 区分启发式提示与已证实违规；不自动放宽设计原则或改写布局。

### User Story 5 - 安装后的工作流与接口保持一致 (Priority: P2)

作为使用不同 coding agent 和本地平台的维护者，我需要安装后的 skill 能按文档执行相同流程，旧项目继续可用，新能力的验收能被重复执行。

**Why this priority**: 框架优化必须覆盖分发、指令、CLI 与实际脚本，不能只在源码目录或一个模型会话中有效。
**Independent Test**: 在隔离安装目录中按通用研究、教学、内部汇报、局部编辑场景执行 smoke；验证旧调用接口、失败路径、必需依赖与测试结果。

**Acceptance Scenarios**:

1. **Given** 旧项目没有新增质量元数据，**When** 预览、导出或旧式校验，**Then** 仍可运行；新增完整交付检查明确指出缺少的内容覆盖。
2. **Given** 测试准备步骤失败，**When** 运行回归，**Then** 测试失败；缺可选依赖时显式跳过并统计缺失能力。
3. **Given** 命令声明了筛选或修复选项，**When** 调用，**Then** 实际行为与文档一致；未实现的修复不得静默忽略。
4. **Given** 导出命令以结构化模式失败，**When** 调用方读取结果，**Then** 能可靠区分成功、质量问题与执行错误。
5. **Given** 从分发包安装到新目录，**When** 运行工作流，**Then** 所需模板、契约和脚本均存在，且不依赖开发机的绝对路径或本地实战 case。

### Edge Cases

- 同一数字有不同单位、年份、统计分母或实绩/预测标签；舍入与合法单位换算。
- 内容存在于表格、图表、备注、富文本或由用户指定的模板中。
- 旧版报告、未知告警代码、损坏报告、部分输出和遗留旧文件。
- 单页、固定多页、局部截图、跨页引用、编辑后上下文或来源变更。
- 没有 Chrome、字体、Pillow 或可选联网服务；测试依赖缺失。
- 不透明纯色背景与照片、渐变、透明叠层的可测量范围不同。
- 网络超时、读取挂起、单槽异常、并发结束乱序和整体预算耗尽。
- 来源许可不明；明确许可信息存在但用途不匹配；不能自动宣称获商业授权。

## Requirements

### Functional Requirements

- **FR-001**: 每次质量结论 MUST 声明输入版本、覆盖页面/格式、实际执行的方法、结果、证据及原因。
- **FR-002**: 系统 MUST 区分检查通过、明确降级、未检查与已证实失败；未检查不得被汇总为完整通过。
- **FR-003**: 完整交付 MUST 核验任务要求的全部格式、页数、页序、资源完整性、报告时效及已知信息损失。
- **FR-004**: 渲染异常、错误占位和导出内容替换 MUST 被调用方观察并纳入交付判定。
- **FR-005**: 生成前 MUST 能获得目标输出的能力边界；导出后 MUST 保留实际降级及不支持项的记录。
- **FR-006**: 新工作流 MUST 使用共享任务、设计、内容与逐页意图，并能识别写作过程中约束版本漂移。
- **FR-007**: 内容 MUST 区分外部事实、用户数据、派生结果、教学示例与假设；仅按对应类型要求依据。
- **FR-008**: 外部事实 MUST 有可定位依据；引用存在、来源可访问和来源支持主张 MUST 分别记录。
- **FR-009**: 确定性内容检查 MUST 覆盖同口径冲突、悬空引用、有效换算、已支持公式、以及正文/表格/图表绑定差异；无法确定的语义冲突只能提出复核项。
- **FR-010**: 顺序与并行写作 MUST 经过全稿主写手审阅；编辑任务 MUST 遵守用户修改范围并复核受影响关联。
- **FR-011**: 素材任务 MUST 有可配置的来源尝试预算与整体预算，持续报告进度并保留每项失败诊断。
- **FR-012**: 一个来源下载或筛选全部失败 MUST 能触发下一来源；预算耗尽后的未解决项不得丢失。
- **FR-013**: 离线执行 MUST 不产生隐式网络请求；联网资料、图片和视觉模型访问必须遵守任务授权；安装准备与离线运行分开。
- **FR-014**: 素材替代 MUST 尊重装饰性/身份相关等语义，保留来源、许可已知程度与降级方式。
- **FR-015**: 文本检查 MUST 区分估算与真实测量，覆盖富文本及固定行高；不支持的测量范围 MUST 明示。
- **FR-016**: 对比度/遮挡等检查 MUST 在已验证能力范围内决定阻断，复杂背景或未知可见性不得伪装为确定结果。
- **FR-017**: 节奏建议 MUST 保留固定页数、稳定页身份和显式内容语义；统一元素数及标题长度不能作为通用质量判据。
- **FR-018**: 旧项目、有效 CLI 调用和既有结构化字段 MUST 保持可用；新完整验收不得给旧项目虚构内容核验结果。
- **FR-019**: 结构化输出、退出结果、报告与实际行为 MUST 一致；测试准备失败和必需检查缺失不得显示为成功。
- **FR-020**: 安装包 MUST 包含运行所需的新规范、模板及工具；回归 MUST 由通用能力样本构成，不能依赖指定实战项目。
- **FR-021**: 本功能 MUST 提供有已知正负结果的契约与回归测试；对高风险能力检验漏报、误报和未检查边界，避免仅断言实现存在。

### Key Entities

- **任务上下文**: 目的、受众、操作范围、输出格式、固定/弹性页数、内容扩展及联网策略。
- **逐页意图**: 稳定身份、读者任务、主要结论、前提、引用主张、布局意图和连续讲解关系。
- **来源与主张**: 依据位置、主张类型、数值/单位/口径、支持关系、推导关系与复核记录。
- **素材需求与尝试**: 槽位语义、替代许可、预算、候选结果、诊断与实际使用素材。
- **能力声明**: 输出目标支持的表示方式、限制与对应回归覆盖。
- **质量证据与交付决定**: 检查范围、输入版本、发现、产物身份与是否满足交付条件。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 通用失败样本中，图表失败、无关图标替代、缺产物、页序错误、过期报告和缺必需检查的检出率为 100%；范围限于明确定义的回归矩阵。
- **SC-002**: 已知正确的黑白对比、教学示例、用户数据、合法单位换算与连续讲解样本不出现错误阻断。
- **SC-003**: 外部研究、教育、内部汇报、局部编辑四类场景均能完成适用的来源/范围检查，且不要求私人数据或示例拥有公网链接。
- **SC-004**: 可控挂起场景在配置预算加最多 2 秒清理时间内返回；运行期间每个不超过 5 秒的窗口有进度或心跳。
- **SC-005**: 声明完整交付的回归样本中，要求的格式、页面集合及输入版本匹配率为 100%；任何已接受替代均可定位。
- **SC-006**: 必需测试全部真实执行，准备失败不能被统计为通过；可选跳过全部具备原因和缺失覆盖记录。
- **SC-007**: 固定页数与局部编辑样本保持原页数和未授权范围；相同输入及策略产生相同共享约束。
- **SC-008**: 隔离安装后的工作流不依赖源码目录、实战 case 或开发机绝对路径；离线测试的未授权远端调用数为零。

## Assumptions

- 本轮仅产出规格、计划、契约与任务，不实现业务功能，不改实战文稿，不 commit/push，不发布 npm。
- 继续保留本地优先和默认 PPTD/PPTX/HTML 三格式交付，不新增服务、数据库、强制模型供应商或通用工作流平台。
- 外部事实审阅可由主写手依据用户材料或已授权研究完成；系统不承诺自动证明所有事实真实。
- 现有项目可以没有新元数据；新工作流默认生成所需上下文，旧项目通过显式补充恢复完整覆盖。
- 本轮不承诺任意 PPTX 无损往返、不统一重做全部设计系统、不新增整套图表引擎、不默认自动扩高文本框。
- 既有宪章的设计原则不因启发式误报而被废除；用户明确模板和任务要求仍按上层指令优先。
- 实战样本只用于探索与压力复验；发布验收采用自包含、无敏感资料的通用样本。
